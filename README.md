
## 1. サービス概要（※最後に書いてOK）

ダイエットが続かない人向けに、猫の育成要素を取り入れたダイエットアプリです。
毎日体重を記録することで、"ガリガリにゃんこ"を"まん丸にゃんこ"まで育てましょう!!
猫のために頑張ることで、ダイエットのモチベーションを維持できます。

## 5. 既存サービス・競合調査

### 5-1. 似たサービス

- サービス名：Habitica（ハビティカ）
- URL：https://habitica.com/static/home
- どんなことができるか：体重測定や間食我慢などの目標を自分で登録。達成すると経験値や通貨を獲得し、キャラがレベルアップ。サボるとHPが減るペナルティ機能貯めた通貨でペットの卵や装備を購入・育成

### 5-2. それでも作りたい理由

このアプリは、ダイエットを「自分のために頑張るもの」ではなく、「猫を元気に育てるために続けるもの」へと変えることに価値があります。

また目標体重を達成することで頑張った人がが喜ぶのはもちろんですが、頑張ってくれたおかげで猫が元気になったという思いやり精神を育むアプリはHabiticaとは異なっていると思います。

自分のためだけだと人間どこか甘えてさぼってしまうが、猫のため、自分以外のためだと人間頑張れる実体験からこのアプリを作りたいです。

### 5-3. このアプリの価値は

自分以外のために頑張って結果がでたときには何にも得難い達成感が味わえると思います。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails
→カリキュラムで学習済みであり、CRUDや認証機能を効率よく実装できるため、開発期間内でMVPを完成させやすい。

- DB：PostgreSQL
→体重記録のような時系列データを扱いやすく、ユーザーごとの記録管理に適しているため採用します。

- デプロイ先：AWS 
→ Webアプリケーションを公開し、実際のユーザーが利用できる環境を構築するため。

- 使用予定ライブラリ：
・devise（ログイン機能）
・ActiveHash　猫の種類や成長段階など固定データの管理
・chartkick（体重の変移のグラフ）

### 10-2. 技術選定の比較検討

Ruby on RailsとDjango（Python）を比較した結果、Djangoでも今回必要な機能は実装可能だが、Railsはカリキュラムで学習済みであり、CRUDや認証機能の実装経験があるため、開発期間内でMVPを完成させやすいと判断し、Ruby on Railsを採用する。

PostgreSQLとMySQLのどちらでも今回のアプリは実装可能だが、Railsとの組み合わせで利用することを想定しており、ユーザー・体重記録・猫の状態などの関連するデータを管理しやすいため、PostgreSQLを採用する。

### 10-3.キャッチアップ不足の懸念

・Railsのローカル開発経験はあるが、AWSへのデプロイ経験が不足している。

・グラフの実装経験がない。
